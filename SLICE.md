## The composition

- **TLS and certificates come from the corpus's canonical implementation: OpenSSL** (libssl, linked directly from C). This is the one place the slice names an implementation and the build uses exactly it.
- **HTTP/1.1 and HTTP semantics are implemented by phweb itself**, in portable C99, because the corpus's recorded implementations (curl, nginx, Apache httpd) are a client library and two full servers — composing them would mean embedding someone else's server, not writing one for phcc. The corpus supplied the *specification*; the implementation is this build's own, and the tests are its evidence. Recorded here rather than attributed to the corpus, per RFC Box discipline.
- **Phext is not in the slice at all** — it is not an IETF standard and the corpus correctly contains no entry for it. Phext conventions (delimiter hierarchy, coordinate addressing) come from the reference material in `~/workspace/phext/` (libphext conventions, `parse_phext.py`). See GAP.md.

## Followed redirect

- **RFC 8446** (TLS 1.3, coordinate 1.1.1/1.2.1/1.1.8446) is the number everyone cites — but the corpus records it **superseded**, obsoleted by RFC 9846 with successor coordinate 1.1.1/1.2.1/1.1.9846. Per MOAT rules the superseded entry is kept and annotated; the slice takes the successor, 9846. Same title, same canonical implementation (OpenSSL).
